## 2. 背景与目标

用户读英文原版书时的核心摩擦是「查词/看译文打断阅读流」。现有工具要么做「译文对照」（沉浸式翻译），要么做「词频高亮」（蒙哥），无人把「在原文上做系统化、多维分类的彩色虚线标注 + 段译插入」做成阅读器的核心体验。

**要达成**：
1. 让用户在不跳出原文的情况下完成查词、看段译。
2. 用「多维彩色虚线 + 虚线下小号字释义」把原文变成可视觉化的学习文本。
3. 用「段译插入」提供连贯阅读，眼睛下移即得译文。
4. 以开源（MIT）+ BYOK 建立信任与低成本门槛，探索 Open Core 订阅变现。

## 3. 目标与非目标

### Goals（首版达成）
- G1：支持导入并阅读 EPUB / TXT 英文电子书（Android 首发）。
- G2：点选单词/词组，弹窗展示翻译（外接模型，BYOK）。
- G3：模式一——单词/词组级彩色虚线 + 虚线下小号字释义；划线切分与分类由外接模型完成，颜色映射按本地四类规则。
- G4：模式二——整段翻译，译文插入本段之后、下一段之前。
- G5：多模型可切换（国内模型为主，可配海外模型），用户自配 API key。

### Non-Goals（首版不做）
- 不含 PDF（首版）。
- 不含付费书城 / 内置正版内容合作。
- 不含背单词复习系统（遗忘曲线/卡片/测试）。
- 不含 TTS 朗读、视频/网页/OCR 翻译。
- 不含开发者内置翻译额度（开发者不承担模型成本）。
- 不含社交/打卡/社区、内容分享。
- 不写实现代码、不选型具体技术栈（PRD 只到需求/验收层）。

## 4. 目标用户与角色

### Persona
**「阿琳」**：25–40 岁，有基础英语能力，持续读英文原版书/公版书；能自行找到并导入电子书；会在手机碎片时间阅读；愿意为「降低阅读摩擦」付少量订阅费；不追求应试背单词。

### 角色与权限（本产品为单用户客户端 + 开源，无多租户）
| 角色 | 权限 |
|---|---|
| 普通用户（未订阅） | 基础点查弹窗、基础虚线标注（有限分类）、有限段译次数 |
| 订阅用户 | 全部分类着色、无限/更多段译、高级功能 |
| 开源贡献者 | 访问源码（MIT），无运行时权限差异 |

## 5. 用户场景与用户故事

### US1（P0）—— 导入并打开英文书
作为用户，我希望导入 EPUB/TXT 英文书并打开阅读，以便在手机上开始读英文原版书。

### US2（P0）—— 点选查词/词组
作为用户，我希望点选一个单词或词组后弹出翻译，以便不离开原文就能看懂。

### US3（P0）—— 单词/词组级彩色虚线标注（核心差异点）
作为用户，我希望系统用不同颜色虚线划出单词/词组、并在虚线下用更小字号标注意思，以便我一眼看出词性、难度、哪些词我还没查过。

### US4（P0）—— 切换颜色分类方式
作为用户，我希望切换「词性/是否点击/高考四六级/词频」等分类方式，以便按我关心的维度看标注。

### US5（P1）—— 整段翻译并插入
作为用户，我希望选中一段后译文插入本段之后、下一段之前，以便连贯阅读不顺处。

### US6（P0）—— 配置模型 API key
作为用户，我希望配置自己的模型 API key（可多模型切换），以便划线与翻译能力可用。

### US7（P1）—— 订阅高级功能
作为用户，我希望订阅后解锁全部着色分类与更多段译，以便获得完整体验。

### US8（P2）—— 阅读进度/书签/最近阅读
作为用户，我希望保留阅读进度、书签与最近阅读列表，以便下次继续。

### US9（P2）—— 标注数据的本地保存与导出
作为用户，我希望我的「已查词/已划线」状态本地保存，并可导出，以便积累与备份。

## 6. 功能需求

> 每条标注来源：〔MRD 事实〕/〔假设〕/〔TBD〕，并给优先级。

### 6.1 阅读器核心（模块 R）

**FR-R1 电子书导入与解析**〔MRD 事实〕P0
- 支持导入 EPUB、TXT。
- 解析后正确渲染正文文本流，保留章节结构。
- 验收：导入一个标准 EPUB 与一个 UTF-8 TXT 均能正确显示章节与正文；非法/损坏文件给出可理解错误提示。

**FR-R2 阅读视图**〔MRD 事实〕P0
- 支持字体大小、行距、主题（浅/深）调整。
- 支持翻页/滚动两种阅读方式（至少一种）。
- 验收：设置即时生效并持久化；翻页/滚动不出现内容错位。

**FR-R3 阅读进度与书签**〔假设〕P2
- 自动保存每本书的阅读位置；支持手动书签。
- 验收：退出重进恢复到上次位置；书签可增删并跳转。

### 6.2 点选查词（模块 D）

**FR-D1 点选取词**〔MRD 事实〕P0
- 点击单词选中；长按或拖动选中词组/短句。
- 验收：单词点击后 ≤ 300ms 内弹窗出现（网络正常时）；词组/短句拖动选择准确。

**FR-D2 弹窗翻译**〔MRD 事实〕P0
- 弹窗展示：原文、译文、可能的词性/音标（如有）。
- 触发外接模型翻译；失败时给出重试与「检查 key」提示。
- 验收：Given 用户已配置有效 key，When 点选一个词，Then ≤ 3s 内弹窗显示译文；Given key 无效，When 点选，Then 弹窗提示配置错误且不崩溃。

**FR-D3 弹窗内收藏/标记已查**〔假设〕P1
- 弹窗内可「加入生词」与「标记已查」，更新该词的「是否点击查看」状态。
- 验收：标记后，该词在「是否点击」分类下的虚线颜色随之变化（本地即时更新）。

### 6.3 划线标注引擎（模块 A，核心差异点）

**FR-A1 模型划线切分**〔MRD 事实（用户澄清）〕P0
- 对当前阅读段落，调用外接模型识别并切分「有实际意义的单词/词组」（如短语动词、固定搭配、习语、专有名词），而非机械逐词。
- 模型返回：每个划线段落的文本范围、类型（词/词组）、词性（POS）等分类信息。
- 验收：Given 有效 key，When 打开一页/一段，Then 段落内出现按意义划分的单词与词组划线段（而非每词都划）；Given 模型不可用，Then 降级为本地词典/逐词基础标注（见 FR-A4）。

**FR-A2 虚线下小号字释义**〔MRD 事实〕P0
- 每个划线段下方，以更小字号标注其中文释义（由模型返回或本地词典兜底）。
- 验收：划线段下方可见小号释义；不遮挡正文、不破坏行距；字号明显小于正文。

**FR-A3 四类颜色分类映射**〔MRD 事实（用户澄清）〕P0
- 本地预置四类颜色分类规则：①词性；②是否点击查看；③高考四六级分级；④词频分级。
- 用户可切换当前激活的分类方式；切换后同文本的虚线颜色按新分类重绘。
- 分类方式可扩展（后期可新增分类）。
- 验收：Given 同一段文本，When 分别切换四类分类，Then 划线段颜色按对应规则变化，且「是否点击查看」状态在本地更新后即时反映到颜色。

**FR-A4 降级策略**〔假设〕P1
- 模型不可用/未配 key/超时/限流时，降级到本地词典逐词标注（词性、词频、高考四六级尽量用本地词表），「是否点击查看」本地状态不受影响。
- 验收：断网或无 key 时，阅读器仍可展示基于本地词表的单色/基础标注，并提示「模型标注不可用」。

**FR-A5 标注结果缓存**〔假设〕P1
- 同一段落的模型划线结果本地缓存，避免重复调用/重复计费。
- 验收：再次打开同段落不重复调用模型（离线可读缓存）；缓存可按书清空。

### 6.4 段落翻译（模块 P）

**FR-P1 整段翻译插入**〔MRD 事实〕P1
- 选中一段后，译文以「引用块/区分样式」插入本段之后、下一段之前。
- 验收：Given 选中一段，When 触发段译，Then 译文出现在本段与下一段之间；样式与原文可区分；可收起/删除该译文。

**FR-P2 段译上下文感知**〔假设〕P2
- 段译请求携带必要的上文（如前 1–2 段）以提升连贯性（如模型支持）。
- 验收：模型 API 支持上下文时，译文一致性优于无上下文（评测标准见第 16 章）。

### 6.5 模型配置（模块 M）

**FR-M1 BYOK 模型配置**〔MRD 事实〕P0
- 用户可添加一个或多个模型端点（服务商 + API key + 模型名 + base URL，如适用）。
- 支持国内（DeepSeek/通义/豆包/智谱等）与海外模型；提供国内常用模型的一键接入模板。
- 验收：Given 用户按模板填入 key，When 保存并测试连接，Then 返回成功/失败明确提示；多个模型可切换当前使用项。

**FR-M2 Key 安全存储**〔MRD 事实〕P0
- API key 本地加密存储，不随日志/崩溃上报明文外泄。
- 验收：key 不以明文落盘；崩溃日志与埋点不含 key。

**FR-M3 用量与成本提示**〔假设〕P2
- 显示近 N 次/本会话模型调用量（按 token/次数，视模型返回），提示「费用由用户承担」。
- 验收：用户可在设置中查看用量概览；首次使用前明确告知 BYOK 成本归属。

### 6.6 订阅与 Open Core（模块 S）

**FR-S1 免费版 vs 订阅版功能边界**〔MRD 事实〕P1
- 免费版：点选查词、基础虚线标注（如仅「是否点击」一类）、有限段译次数（如每日 N 段，TBD）。
- 订阅版（¥12/月、¥88/年）：四类着色全开、更多/无限段译、离线缓存增强等高级功能。
- 验收：未订阅用户访问订阅功能时，触发付费墙并明确告知权益；订阅后功能即时解锁。

**FR-S2 订阅购买与恢复**〔MRD 事实〕P1
- 应用内购买（App Store/Google Play 内购，或大陆安卓渠道支付，TBD）；支持恢复购买。
- 验收：订阅成功、到期、续费、恢复购买均有明确状态呈现。

**FR-S3 开源边界**〔MRD 事实〕P1
- 代码 MIT 开源；订阅解锁的「高级功能」以功能开关/旗舰特性形式存在，不将用户私有数据与订阅状态耦合进源码分发的核心。
- 验收：源码仓库 MIT 协议；编译出的 App 在未订阅时功能边界与 FR-S1 一致。

## 7. 非功能需求

### 7.1 性能
- NFR-P1：冷启动（App 启动到可进入书架）≤ 2s〔假设〕。
- NFR-P2：打开一本已解析 EPUB 到显示正文 ≤ 1.5s〔假设〕。
- NFR-P3：点选查词弹窗 ≤ 300ms（本地词典兜底）；模型翻译 ≤ 3s（网络正常）〔MRD 事实〕。
- NFR-P4：段落级模型划线（单屏段落）≤ 3s，且不阻塞翻页滚动〔假设〕。
- NFR-P5：单屏滚动帧率流畅（标注渲染不导致明显卡顿）〔假设〕。

### 7.2 可扩展性
- NFR-S1：单本书 EPUB 文本量 ≥ 50 万字可正常加载与标注（长文）〔假设〕。
- NFR-S2：标注缓存按书管理，缓存总量可控（可清理）〔假设〕。
- NFR-S3：模型调用可并发/串行策略明确，避免同屏大量划线段触发接口风暴〔假设〕。

### 7.3 可用性与可靠性
- NFR-A1：模型不可用/超时/限流时，App 不崩溃，降级到本地标注并提示〔MRD 事实〕。
- NFR-A2：本地阅读数据（进度/书签/标注状态）本地持久化，闪退后不丢失〔假设〕。
- NFR-A3：无账号体系（单机优先），无服务器单点；若后续加同步则另行定义〔假设〕。

### 7.4 安全
- NFR-SEC1：API key 本地加密存储，不明文落盘、不进日志/崩溃上报/埋点〔MRD 事实〕。
- NFR-SEC2：本地书与标注数据不做未经用户同意的上传〔MRD 事实〕。
- NFR-SEC3：防注入：模型返回的文本按纯文本渲染，不执行脚本/HTML（EPUB 内容与模型返回均视为不可信输入）〔假设〕。

### 7.5 合规与数据
- NFR-C1：符合 PIPL（《个人信息保护法》）：无强制登录即可用；如收集个人信息需告知与同意〔MRD 事实〕。
- NFR-C2：不含盗版书源；不支持分享译文/书（避免版权与内容合规风险）〔MRD 事实〕。
- NFR-C3：大陆分发需满足 ICP/备案与内容审核要求（App 审核合规）〔TBD，需核实〕。
- NFR-C4：接海外模型时的跨境数据传输风险由用户自担（BYOK）；App 不代传用户书内容到开发者服务器〔假设〕。
- NFR-C5：数据保留与删除：用户可本地清空标注/书/缓存；卸载即清除〔假设〕。

### 7.6 可观测性
- NFR-O1：崩溃上报（去标识化，不含 key 与书内容）〔假设〕。
- NFR-O2：产品埋点：查词次数、划线触发/切换分类次数、段译次数、订阅转化、留存（见第 12 章增长埋点）〔MRD 事实〕。
- NFR-O3：模型调用失败率/延迟/限流监控（本地统计，供用户与维护者查看）〔假设〕。

### 7.7 国际化与本地化
- NFR-I1：首版界面中文为主；英文书为阅读对象，不做全文 UI 多语言〔MRD 事实〕。
- NFR-I2：释义语言可选中英双语（如模型支持）〔假设〕。

### 7.8 无障碍
- NFR-ACC1：基础无障碍——系统字体缩放、颜色对比度满足可读；虚线颜色区分不依赖单一色觉（提供形状/亮度辅助）〔假设〕。
- NFR-ACC2：目标为 WCAG 2.1 AA 于核心阅读界面（文字对比度）〔假设〕。

### 7.9 兼容性
- NFR-COMP1：Android 首发，目标系统版本范围〔TBD，需确认〕；主流屏幕尺寸/分辨率适配（手机竖屏优先）〔MRD 事实〕。
- NFR-COMP2：iOS 后续版本，随 MVP 后确认〔MRD 事实〕。

### 7.10 可维护性与质量
- NFR-Q1：核心划线/翻译逻辑可单测（需求层级：给定段落与模型返回，产出确定标注结果）〔假设〕。
- NFR-Q2：源码带 README 与贡献指南（见第 12 章开源章节）〔假设〕。

## 8. 数据需求（需求层级，不写建表 SQL）

### 8.1 实体与字段（概念模型）
- **Book（书）**：id、标题、作者、文件路径、格式(epub/txt)、导入时间、解析状态、总字数。
- **ReadingProgress（阅读进度）**：book_id、章节/位置、更新时间。
- **Annotation（划线段）**：id、book_id、段落定位(章节+字符范围)、文本、类型(词/词组)、pos(词性)、难度分级(高考四六级/词频)、是否已点击、释义、来源(模型/本地词典)、创建时间。
- **UserSetting（设置）**：当前模型配置项、激活的分类方式、主题/字体/行距。
- **ModelConfig（模型配置）**：id、服务商标识、模型名、base_url、加密后的 key、是否当前使用。
- **SubscriptionState（订阅状态）**：平台内购凭据状态、到期时间、权益档位。

### 8.2 约束
- 每条 Annotation 可定位回原文唯一位置（book_id + 字符范围），重排后需能重定位或失效重算〔假设〕。
- 释义字段与「是否已点击」状态可本地更新，不依赖网络〔MRD 事实〕。

### 8.3 生命周期
- 书导入 → 解析 → 阅读/标注 → 缓存 → 删除（可清缓存/删书）；标注随书删除或导出保留〔假设〕。

## 9. 接口与集成需求（API 契约，需求层级）

### 9.1 外接模型接口（BYOK）
- **鉴权**：用户提供 API key，随请求发送（放 Header，如 `Authorization: Bearer`），以各服务商规范为准。
- **翻译接口（点查/段译）**：
  - 请求：`messages`（system 指令 + 用户文本），`model`，可选 `temperature`。
  - 响应：译文文本 + 可选结构化字段（词性/音标）。
  - 错误码需覆盖：401(无效 key)、429(限流)、超时、网络错误、内容过滤拒绝。
- **划线接口（FR-A1）**：
  - 请求：段落文本 + 分类需求（词性/难度等）。
  - 响应（需求约束）：结构化划线段列表——每条含 `text_range`、`text`、`type`、`pos`、`difficulty`、`gloss`。
  - 验收：响应可解析为不重叠的划线段集合，覆盖/不覆盖原文均需可处理。
- **限流与重试**：客户端做基础重试与退避；不实现服务端限流（BYOK 无自有服务端）〔假设〕。

### 9.2 本地词典兜底（FR-A4）
- 本地词表提供词性、词频、高考四六级、释义的离线查询能力。
- 验收：断网时对常见词给出正确词性/释义；对词表外词明确「未收录」〔假设〕。

### 9.3 订阅支付接口
