# AI 执行指导：IntelliJ IDEA Ultimate 完成手机英文阅读器开发

> 适用对象：AI 编程助手（Claude Code / JetBrains AI Assistant / 其他 IDE AI 助手），在 IntelliJ IDEA Ultimate 工作区内执行。
> 配套人工指导见 `docs/dev/人工操作指导.md`。
> 上游依据：`docs/software/技术方案.md`、`docs/prd/产品需求文档PRD.md`。
> 更新说明：2026-08-27 起，IDE 定为 IntelliJ IDEA Ultimate（Android/Kotlin 第一方支持最好）。

## 1. 定位与总原则

你是「需求/方案 → 代码」的执行者，负责在 IntelliJ IDEA Ultimate 工作区产出**可构建、可验收**的代码。必须遵守：

1. **只做当前任务，不越界**：首版不含 PDF、背单词、TTS、付费书城、分享。被要求做这些时先停下确认。
2. **先读上游，再动手**：每个任务开工前，读对应 PRD 验收标准（`docs/prd/...`）与技术方案选型（`docs/software/...`），不凭记忆硬写。
3. **落到需求层级 + 可验收**：写代码时对齐 PRD 的功能需求编号（FR-R1/R2、FR-D1/D2、FR-A1…FR-A4、FR-P1、FR-M1/M2、FR-S1/S2）。验收标准是「功能是否满足」，不是「代码写得好看」。
4. **不编造版本/许可**：引第三方库版本、许可证、API 价格时，若不确定写「待核实」并标给用户查证，不写死。
5. **安全红线**：API key 不走明文日志/崩溃上报/埋点/提交到仓库；不硬编码 key；不把用户书内容上传到任何非用户配置的服务。

## 2. 上下文（AI 需要知道的背景）

- IDE：IntelliJ IDEA Ultimate（含 Android 插件 + Kotlin 插件，Gradle 构建，内置 Logcat/AVD 管理器）。
- 技术栈：Kotlin（Android 壳）+ WebView（foliate-js 渲染，MIT）+ DOM 标注（`<ruby>` + CSS 虚线）+ ECDICT（SQLite）+ BYOK 多模型 API。
- 核心差异点（不是普通阅读器）：单词/词组由**外接模型切分并分类**，本地用四类颜色映射（词性 / 是否点击 / 高考四六级 / 词频）渲染虚线 + 虚线下小号字释义；段译插入本段后。
- 仓库结构见人工指导第 3 章；模型划线接口约定见技术方案 3.4 与风险 R1。

## 3. 执行规范

### 3.1 通用
- 每完成一个任务，输出：改动文件清单 + 对应 PRD 功能编号 + 如何验证（命令/步骤）+ 已知未完成项。
- 不写「占位 TODO 假装完成」；未做完就明确说「未完成 + 缺什么」。
- 需要用户拍板的阈值/降级方案，用提问确认，不擅自决定。

### 3.2 代码质量
- Kotlin 壳：可读性优先，核心逻辑可单测；Web 层：ESLint/Prettier 规范。
- 标注/翻译逻辑要能离线单测（给定段落 + 模型返回 → 确定标注结果），不做成只能连真机验证的黑盒。

### 3.3 桥接与安全
- 壳层↔Web 层消息接口先定义好（调用/返回/错误），再写实现。
- key 注入 Web 层时仅内存传递，不写入 DOM/`localStorage` 明文（技术方案要求 FR-M2）。

## 4. 分阶段任务清单（按序执行）

### M1 技术 spike（先验证 R1/R2/R4，不写完整功能）
- T1.1：`web/` 用 foliate-js 加载一个标准 EPUB，分页显示。
- T1.2：单屏段落手工叠 `<ruby>`（`ruby-position: under`）+ CSS 虚线，Android WebView 渲染可读。
- T1.3：最小脚本调 1–2 家低价模型（Qwen3-Plus / 豆包 Lite / GLM-4-Air），要求结构化返回划线段（text_range/type/pos/difficulty/gloss），统计可解析率。
- T1.4：Kotlin 壳开 WebView 加载 `web/`，跑通桥接（调用→返回）。

**验收**：结构化解析率、WebView 兼容性、`<ruby>` 渲染三项达到人工指导 4.1 阈值（阈值由用户确认）。

### M2 MVP（按模块，每模块附 PRD 验收）
- T2.1 文件导入：EPUB/TXT 导入 + zip.js 解压（对齐 FR-R1）。
- T2.2 本地词表：ECDICT 转 SQLite，词性/词频/高考四六级查询 + 释义兜底（对齐 FR-A4）。
- T2.3 标注引擎：段落渲染 → 模型划线（带上下文）→ DOM 叠加 `<ruby>` → 按激活分类着色（对齐 FR-A1/A2/A3/A5）。
- T2.4 点选查词：选中 Range → 模型/本地词典 → 弹窗（对齐 FR-D1/D2/D3）。
- T2.5 段译插入：选中段 → 译文插入本段后，分页模式验证版式（对齐 FR-P1）。
- T2.6 BYOK 配置：多服务商适配 + key 安全存储 + 连接测试（对齐 FR-M1/M2/M3）。
- T2.7 订阅开关：免费/订阅功能边界（对齐 FR-S1/S2）。

**验收**：逐条过 PRD 第 6 章 P0 验收标准 + 第 7 章关键非功能项。

### M3 内测/发布
- T3.1 崩溃上报接入（去标识化）。
- T3.2 README + 贡献指南（MIT）。
- T3.3 打 APK 供灰发。

## 5. 边界约束（遇到就停下确认）

- 涉及付费书城、背单词系统、TTS、视频/网页/OCR、PDF 精准划词 → 非首版，停下。
- 要求把 API key 或书内容写入日志/仓库/第三方服务 → 拒绝并说明安全红线。
- 要求固定绑定单一模型或硬编码模型价格 → 停下，改用多服务商适配层 + 标注「待核实」。
- 涉及大陆应用商店上架/支付的合规细节 → 只给方案，不替用户确认合规。

## 6. 交接给人工的内容格式

每阶段结束时，给出：
1. 本阶段完成的 PRD 功能编号清单。
2. 未完成项 + 原因。
3. 需人工验证的项（真机调试 / 阈值确认 / 降级拍板）。
4. 需要用户查证的外部事实（许可证 / 版本 / 价格）。

## 7. 一句话提醒
本产品的成败在 M1 spike 的 3 个风险（模型结构化返回、WebView 兼容、`<ruby>` 渲染），不在堆功能。**优先把 M1 跑通，再谈 MVP。**
