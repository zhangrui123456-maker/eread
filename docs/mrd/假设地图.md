# 假设地图（Assumptions）

日期：2026-08-27

按「承重程度 × 可验证速度」排序。★ = 承重假设（错了就塌）。

## 一、痛点与需求假设

- ★A1：泛英语阅读爱好者在手机上读英文原版书时，最大的摩擦是「查词/看译文会打断阅读流」，且现有工具（划词弹窗、双语对照）仍不能满足。
  - 证据状态：**待验证**（无一手数据）。竞品存在（蒙哥/沉浸式翻译）说明痛点存在，但「彩色虚线+小号字标注」这一具体解法未被验证。

- A2：「按词性/是否点击/难度分级着色」能帮助用户建立词汇的视觉记忆与「哪些词我查过了」的进度感。
  - 证据状态：**待验证**。蒙哥已有「词频分级颜色」先例（公开资料，2026-08-27 查证），说明「分级着色」有用户接受基础，但「虚线+小号字」与「是否点击」维度是新的。

- A3：段落级「译文插入本段后」比「底部/侧栏显示译文」更利于连贯阅读。
  - 证据状态：**待验证**。沉浸式翻译采用双语对照（译文紧邻原文）已验证该方向有需求（公开资料，2026-08-27 查证），但「插入式」与「对照式」的优劣未验证。

## 二、用户与市场假设

- B1：目标人群（大陆泛英语阅读爱好者，能自己找到并导入英文原版书）规模足够支撑一个开源/小众产品。
  - 证据状态：**证据不足**。中国英语学习软件市场有权威报告但公开摘要未披露具体金额（公开资料，2026-08-27 查证，数值空缺）。TAM 无结论。

- ★B2：目标用户愿意为「高级功能订阅」付费（Open Core 变现成立）。
  - 证据状态：**待验证**。竞品有付费先例：蒙哥买断 €2.99、欧路 AI 会员 ¥28/月起、沉浸式翻译 ¥69/月或 ¥588/年（公开资料，2026-08-27 查证）。但「开源产品的订阅转化率」无数据。

## 三、产品与技术假设

- C1：BYOK（用户自带 API key）是可行路径，用户愿意且能自行配置模型 key。
  - 证据状态：**部分验证**。沉浸式翻译免费版即支持自接 API（公开资料，2026-08-27 查证）；KOReader 有 KoTranslate 多服务插件（公开资料）。但「普通消费者」配置 key 的门槛仍是风险（见 Red Team）。

- ★C2：EPUB 可稳定实现「单词级精准划线 + 虚线下小号字标注」且不破坏排版。
  - 证据状态：**待验证**。EPUB 为 HTML/CSS 结构，理论上可做 inline 标注；但跨平台渲染一致性、长文性能、与阅读器排版引擎的集成复杂度是主要工程风险。

- C3：PDF 重排 + 划词可行。
  - 证据状态：**高风险/待验证**。PDF 无稳定文本流，划词与插入段译难度远高于 EPUB。建议首版砍掉 PDF 或仅支持「整页翻译」，见 MVP。

- C4：国内大模型（DeepSeek/通义/豆包/智谱）翻译质量可满足泛阅读需求。
  - 证据状态：**公开资料/待验证**。多模型可切换降低单点风险；翻译质量需在真实英文原著样本上评测。

## 四、商业与合规假设

- D1：Open Core 模式（开源 + 订阅）在移动 App 场景可行，用户能通过应用商店内购订阅。
  - 证据状态：**待验证**。开源 + 移动 App 内购在海外有先例（如开源阅读器的赞助/高级版），大陆安卓渠道对「开源 App 内购」的合规与分成政策需核实（公开资料，2026-08-27 待验证）。

- D2：用户导入自有书（个人使用）不触发重大版权风险。
  - 证据状态：**公开资料/待验证**。个人自用导入通常风险可控，但若后续加「分享译文/书」功能则风险上升；大陆内容合规（ICP/网络出版）政策需核实（查证日期待补）。

## 假设地图结论
承重假设集中在 A1、B2、C2：**「彩色虚线+小号字标注」是否真解决痛点、用户是否愿付费、EPUB 能否稳定实现**。这三项决定 Go/No-Go，是验证计划与 Red Team 的重点。
