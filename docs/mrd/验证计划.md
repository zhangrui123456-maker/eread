# 验证计划（Validation）

日期：2026-08-27 · 原则：cheapest tests 优先，能 1 周内跑完的先跑。

## 验证命题（对应承重假设）

**P1（对应 A1）：** 「彩色虚线 + 小号字标注」的阅读方式，比「高亮」或「弹窗查词」更能让用户持续读下去。
**P2（对应 B2）：** 目标用户愿意为高级功能（如整段翻译、高级分类着色）付费订阅。

## 验证项

### V1：低成本交互 demo + 用户访谈（concierge / Wizard of Oz）
- 假设：P1。
- 方式：先用静态 HTML/原型图（不写完整 App）做 3 页「同一段英文原版书」的三种呈现对比——A 高亮查词、B 弹窗查词、C 彩色虚线+小字标注+段译插入；邀请 5–8 名泛英语阅读者（豆瓣/知乎/小红书的原版书读者）访谈，让其选偏好并说明理由。
- 指标：偏好 C 的比例；对「能否看懂分类颜色」的理解度；愿意「长期使用」的意愿分。
- 通过阈值：≥60% 首选 C 或「C 明显更易读」；且 ≥2 人主动表达「会为段译/高级着色付费」（需用户确认阈值）。
- 成本/周期：0 现金成本，1 周内。
- 证据状态：待验证。

### V2：落地页 + waitlist（假门测试）
- 假设：P2。
- 方式：做一个单页落地页，展示产品截图/动图与「开源免费 + 高级功能订阅」说明，放「获取内测资格」按钮；在小红书/知乎/英文原版书社群小范围投放，统计点击→留邮箱/留联系方式转化。
- 指标：落地页访客数、waitlist 转化率、「高级功能」预订/付费意向点击率。
- 通过阈值：waitlist 转化 ≥10%；付费意向点击率 ≥3%（需用户确认阈值）。
- 成本/周期：¥0–数百（域名/托管），1–2 周。
- 证据状态：待验证。

### V3：MVP 灰发（首版功能验证）
- 假设：P1 + C2（EPUB 划线标注可实现且好用）。
- 方式：单平台（建议 Android 首发，避开 iOS 审核周期）EPUB/TXT 阅读器，实现：点查弹窗、单词级彩色虚线 + 小字标注（词性/是否点击两档即可）、整段翻译插入、多模型 BYOK。
- 指标：7 日留存、日均标注/查词次数、段译使用率、崩溃率。
- 通过阈值：7 日留存 ≥20%（阅读类工具参考）；人均日标注 ≥5 次（需用户确认阈值）。
- 成本/周期：个人兼职 4–8 周。
- 证据状态：待验证。

### V4：订阅转化小实验
- 假设：P2 + D1。
- 方式：在 MVP 内放「高级功能订阅」（如：更多分类着色/批量段译/离线词典），跑 2–4 周，看免费→付费转化与金额。
- 指标：付费转化率、订阅客单价、续订意向。
- 通过阈值：转化率与客单价覆盖渠道抽成且为正毛利（需用户确认阈值；个人项目可先看「是否有 ≥1% 用户付费」）。
- 成本/周期：MVP 后 2–4 周。
- 证据状态：待验证。

## 三类门槛（继续 / 调整 / 暂停）
- **继续投入**：V1 通过（≥60% 首选 C）且 V3 的 7 日留存达标。
- **调整方向**：V1 未达首选但「段译插入」单项得分高 → 砍掉复杂着色，聚焦「段译插入」单点。
- **暂停放弃（kill）**：V1 + V2 均未通过（无交互偏好、无付费意向）→ 说明「彩色虚线标注」不是真痛点，停止。

## 需用户确认的阈值
V1、V2、V3、V4 的通过阈值均为建议值，最终由用户确认（个人项目可放宽）。
