# 可行性评分（Feasibility）

日期：2026-08-27

## 技术可行性：3 / 5（中等不确定性）

依据：
- EPUB 为 HTML/CSS 结构，实现「单词/词组级 inline 虚线 + 小号字标注」理论可行（+）；有成熟 EPUB 渲染库可用（+）。
- 但核心差异化交互（多维分类彩色虚线 + 虚线下小字释义 + 段译插入）在移动端的高质量、不破坏排版、长文性能，是**未验证组件**（-）。
- PDF 文本流不稳定，划词与插入段译难度远高于 EPUB，属于「数据难获取/部分需自研」（-）。
- 大模型翻译本身是成熟 API（+），多模型可切换集成可控（+）。

**AI 模型依赖风险**：核心翻译能力完全依赖第三方大模型 API（BYOK）。若某模型下架/改价/改 API，产品翻译功能受影响；但「多模型可切换」缓解单点依赖。**被基础模型吞并风险**：低——本产品价值在「阅读器的标注交互与阅读流」，不在翻译模型本身；通用大模型 App 不做阅读器级标注，短期无吞并迹象。

建议：首版砍 PDF（或 PDF 仅整页翻译），聚焦 EPUB/TXT，可把技术可行性升到 4。

## 商业可行性：2 / 5（单位经济/变现路径未经验证）

依据：
- BYOK 下无模型成本，毛利结构健康（软件 70–90% 区间可达）（+）。
- 竞品付费先例存在：买断 ¥18、订阅 ¥12–35/月（+，公开资料）。
- 但「开源 Open Core + 大陆安卓渠道订阅」的转化与分发路径**未经验证**（-）；开源产品付费意愿通常更低（-）。
- 个人/兼职、无分发预算，冷启动获客渠道缺失（-）。
- 大陆安卓侧载/渠道对开源 App 内购的支持与抽成待验证（-）。

判定：**Explore**（技术 3、商业 2、痛点证据「中」——竞品存在证明痛点，但本产品差异化交互未验证）。

## 痛点证据强度：中
- 用户在付费解决（蒙哥/欧路/沉浸式翻译均有付费用户）→ 痛点存在。
- 但「彩色虚线 + 小号字 + 段译插入」这一具体解法是否比现有解法更优，无证据 → 不能评「强」。

## Go / No-Go / Explore 判定
- 技术 3（未达 ≥4）、商业 2（未达 ≥4）、痛点中。
- → **Explore**：不 Go 不 No-Go，先跑 cheapest tests 验证差异化命题与付费意愿，再重评。
