## 一、技术架构

**Hybrid App**（原生壳 + WebView 渲染）：
- `android/` Kotlin 壳：文件导入(SAF)、SQLite、API key 加密存储(Keystore)、模型调用、内购
- `web/` Web 渲染层：foliate-js 渲染 EPUB + 自研标注引擎 + 桥接

**三页结构**：书架(`index.html`) / 阅读(`reader.html`) / 用户(`user.html`) + 设置页(`settings.html`)，10:80:10 布局（顶栏/内容/底部 tab），设置经 localStorage 三页共享。

**浏览模式**：横向翻页 = 原 EPUB（foliate-js 原生分页）；纵向连贯 = 预处理合并 HTML（JSZip 解压→插图内嵌→单一 HTML），缓存到 IndexedDB。

## 四、关键技术决策与坑

### 1. 模型结构化返回（R1 发现）
模型数不准字符偏移（要求 text_range 时 0% 准）。改为**只返回原文精确子串 text**，客户端 `indexOf` 定位 → 100%。故 schema 以 `text` 为主，`textRange` 可选。

### 2. 虚线标注（核心差异点，多轮定稿）
最终方案：`<ruby class="ann">单词<rt>译文</rt></ruby>` + `ruby-position:under` + `border-bottom: 1px dashed`。
- 根因：真机/模拟器 WebView 对 `ruby-position:under` 渲染不一致；inline-block 的 border 会被撑到容器宽
- 译文加 `ruby-align: center` + `white-space: nowrap`（居中、不占满宽度、不拉大文字间距）

### 3. 离线打包（assets）坑
- `fetch` 不支持 file:// → 用 XMLHttpRequest
- serve 的 clean URL 在 file:// 失效 → 跳转用 `.html#hash` 参数
- `view.open(Blob)` 报 `name.endsWith` → 传 `File([blob], name)`
- 需 `allowFileAccessFromFileURLs=true`（deprecated）
- 返回键/跳转用 `index.html` 不能用 `/`

### 4. 存储结构
- localStorage：设置(`eread-settings`)、书架(`eread-shelf`)、进度(`eread-progress`)、翻译缓存(`eread-translation`)
- IndexedDB：书 Blob(`books`)、预处理结果(`merged:*`)、壁纸(`wallpaper:*`)
- API key：Android Keystore AES-GCM 加密（不落 localStorage 明文）
