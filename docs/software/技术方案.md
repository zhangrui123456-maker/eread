**已确认决策**（来源：用户输入，2026-08-27）：
- 技术方向：**原生壳 + WebView 内嵌 Web EPUB 引擎**（Android 首发，iOS 后续复用 WKWebView）。

## 2. 技术方向决策

在 4 个候选方向中选定「**原生壳 + WebView**」，依据：
- 核心功能「单词/词组级彩色虚线 + 虚线下小号字释义」本质是文本排版问题，与 HTML 的 `<ruby>`（`ruby-position: under`）+ CSS 虚线边框天然契合；Web DOM 实现该能力远低于原生文本布局的工程复杂度（放弃方向 D 纯原生、B Flutter 的主因）。
- Readium 的 Flutter 封装 `flutter_readium` 仅 0.0.1（不成熟）；Readium RN 封装同样不成熟 → 方向 B/C 的核心渲染层风险高（查证日期 2026-08-27）。
- 原生壳（Kotlin）负责文件系统、SQLite、模型 API 调用、内购、系统集成；Web 层负责 EPUB 渲染 + DOM 标注，职责清晰，iOS 后续可复用同一 JS 渲染层。

**放弃理由**：
- Flutter：flutter_readium 0.0.1 不可用；Flutter 文本布局做词下小字内嵌标注困难。
- React Native：Readium RN 封装不成熟，New Architecture 下第三方库兼容需逐个核验，多一层 JS 壳。
- 纯原生双端：两套代码，个人兼职成本翻倍；且原生文本布局实现「词下行内小字」比 DOM 更难。

## 3. 候选技术栈选型对比

### 3.1 移动壳层（App 容器）

| 维度 | Kotlin 原生（选定） | 说明 |
|---|---|---|

### 3.2 Web EPUB 渲染引擎（核心选型）

| 候选 | 许可证 | 维护状态 | 结论 |
|---|---|---|---|
| **foliate-js（选定）** | MIT | 积极维护 | 直接操作 DOM `Range`（不做 CFI），利于词级标注；纯 ES Modules 无依赖；需自行引入 zip 库（推荐 zip.js） |
| epub.js | 宽松（repo 标 NOASSERTION，历史为 Free BSD） | **已停维护**，最后发布 2020-07-01（v0.3.88） | 放弃 |
| readium-js | — | **维护模式**（Readium 官方转向 Mobile/Desktop/Web） | 放弃（Web 版可作备选，但不作主引擎） |

来源：foliate-js README、KDE GSoC 2024 迁移记录、Readium 官方项目页（公开资料，查证日期 2026-08-27）。

**选型理由**：foliate-js 是当前活跃维护的 Web EPUB 渲染器；其「直接操作 DOM Range、不直接用 CFI」的特性，使「在指定文本范围上叠加 `<ruby>` 标注与 CSS 虚线」的实现最直接。epub.js/readium-js 均停维护或维护模式，不适合作新项目主引擎。

**风险与缓解**：foliate-js 主要面向 WebKitGTK（Foliate 桌面），在移动 WebView 需验证兼容性；其「无连续滚动、分页为主」需确认与「段译插入」的交互兼容（见风险清单 R3）。

## 4. 系统架构

**架构风格**：单机客户端 + 内嵌 Web 视图 + 外部模型 API（BYOK），无自有服务端（首版）。

**模块划分**：
- **壳层（Kotlin）**：文件导入与解压、SQLite（ECDICT）、安全存储（Key）、模型 API 客户端（多服务商适配 + 重试）、内购/订阅、设置、崩溃上报。
- **Web 渲染层（foliate-js + 自研标注层）**：
  - EPUB 解析与分页（foliate-js）。
  - **标注引擎**：对段落文本调用模型划线接口 → 得到划线段（text_range/type/pos/difficulty/gloss）→ DOM 叠加 `<ruby>` 注解 + CSS 虚线边框，颜色按「当前激活分类方式 + 本地映射规则」渲染。
  - 段译插入：在目标段后插入译文块。
- **桥接层**：壳层 ↔ Web 层消息通道（模型请求转发、key 注入、订阅状态、标注缓存读写）。

**数据流（点选查词）**：用户点选 → Web 层捕获选中 Range → 桥接传壳层 → 壳层调用模型 API（或本地词典兜底）→ 返回译文 → Web 层渲染弹窗。

**数据流（模型划线）**：打开段落 → Web 层请求 → 壳层调模型（带上下文）→ 返回结构化划线段 → 壳层回传 → Web 层叠加标注 → 结果写入本地缓存（避免重复调用）。

**横切关注点**：错误处理（模型失败→本地词典降级）、日志（去标识化，不含 key/书内容）、配置（多模型切换）。

**架构图（文字描述）**：
```
[EPUB/TXT 文件] → Kotlin 壳（导入/解压/SQLite/Key/内购）
        ↕ 桥接消息
[WebView: foliate-js 渲染 + 标注引擎(<ruby>/CSS) + 弹窗/段译]
        ↕ BYOK
[模型 API（多服务商适配层）]   [本地 ECDICT SQLite（兜底）]
```

## 7. 风险清单与验证计划

| 风险 | 验证门槛（PoC/benchmark） | kill criteria |
|---|---|---|
| R1 模型划线响应格式不稳定（各服务商输出结构不一） | PoC：选 2 家低价模型，对 30 段文本做结构化返回，验证 text_range 可解析率 | 结构化解析成功率 <80% 且无法用提示词约束稳定 → 改用「翻译为主 + 本地词表切分」降级方案 |
| R2 foliate-js 移动 WebView 兼容/性能 | PoC：Android WebView 跑通 EPUB 分页 + 单屏标注，测滚动帧率与内存 | 明显卡顿或崩溃率高 → 换 readium-web 或原生 Readium Kotlin + 自定义标注 |
| R3 分页模式下「段译插入」与排版冲突（foliate-js 无连续滚动） | 原型：验证分页模式下译文块插入的版式表现 | 版式严重错乱且难修复 → 段译改为「覆盖式/侧栏式」而非插入式 |
| R4 词下小字（`<ruby>`）在 WebView 的跨引擎渲染不一致 | 兼容性测试：Android WebView + iOS WKWebView 渲染对比 | 渲染差异导致不可读 → 改为「行间小字/气泡」替代方案 |
| R5 ECDICT 许可或数据质量不满足 | 许可核查 + 抽样质量检查 | 许可不合规或词性/词频准确率过低 → 换词表或仅依赖模型返回 |

无阈值来源处标「需用户确认阈值」；本表阈值为建议值，落地前由用户确认。
